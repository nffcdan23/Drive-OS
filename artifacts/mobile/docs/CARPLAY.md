# CarPlay

Derwent is a CarPlay **navigation** app. Apple granted StarScale Ltd the CarPlay Navigation entitlement, and it's enabled for the App ID `uk.co.starscale.drive.staging`.

| Milestone | What | Status |
|---|---|---|
| 1 | iOS scene lifecycle (`docs/SCENE_LIFECYCLE.md`) | On a phone: works. Background relaunch not yet verified. |
| 2 | Derwent on the CarPlay home screen; minimal native interface | Verified in a car (Ford SYNC): launches and shows the placeholder. Cold launch and disconnect/reconnect not yet verified. |
| 3 | Native Mapbox map in the CarPlay window; map controls | **Implemented, not yet tested.** Swift isn't compiled in CI (Linux has no iOS SDK). Needs Xcode, the Simulator and a car. |

There's still no navigation on CarPlay: no search, routes, guidance, trip estimates, hazards, voice or drive recording. Those come in later milestones. The iPhone app is unchanged.

## Native architecture

```
Info.plist UIApplicationSceneManifest (generated by prebuild)
├─ UIWindowSceneSessionRoleApplication              → EXExpoAppSceneDelegate       (Expo; the iPhone app, unchanged)
└─ CPTemplateApplicationSceneSessionRoleApplication → DerwentCarPlaySceneDelegate  (modules/derwent-carplay)
      connect(interfaceController, CPWindow):
        Mapbox settings in Info.plist?  yes → window.rootViewController = CarPlayMapViewController (Mapbox map)
                                        no  → window.rootViewController = CarPlayPlaceholderViewController (dark grid)
        interfaceController.setRootTemplate(CarPlayMapTemplateController.template)   (CPMapTemplate)
      disconnect: releases the map, the template and the interface controller
```

The local Expo module is `modules/derwent-carplay/`. Expo autolinking finds it; it has no JavaScript and no Expo module.

| File | Purpose |
|---|---|
| `ios/DerwentCarPlay.podspec` | Pod `DerwentCarPlay` (static, built from source). Links `CarPlay` and `CoreLocation`, and depends on `MapboxMaps` with **no version**, so CocoaPods uses the same Mapbox Maps SDK v11 that `@rnmapbox/maps` pins (`~> 11.23.1`). There is one copy of the SDK. |
| `ios/CarPlaySceneDelegate.swift` | `@objc(DerwentCarPlaySceneDelegate)`: the CarPlay scene. |
| `ios/CarPlayMapSettings.swift` | Reads the public token and style from Info.plist. Returns nothing without both, or if the token isn't `pk.`. |
| `ios/CarPlayMapViewController.swift` | The Mapbox `MapView` in the CarPlay window: camera, position marker, logo and attribution. |
| `ios/CarPlayMapTemplateController.swift` | The `CPMapTemplate`: navigation bar, map buttons, panning and drag gestures. |
| `ios/CarPlayPlaceholderViewController.swift` | The dark grid, shown when the map isn't configured. |

The CarPlay screen works without React Native: a CarPlay-first launch, with the iPhone app not running, shows the map without waiting for JavaScript. The module imports no React Native or Expo code (`scripts/check-ios-scene-lifecycle.js` checks this).

## Map configuration

The CarPlay map uses the **same public Mapbox token and Derwent style as the iPhone's Drive map**: `EXPO_PUBLIC_MAPBOX_TOKEN` (`pk.…`) and `EXPO_PUBLIC_MAPBOX_STYLE_URL` (`mapbox://styles/…`), from `artifacts/mobile/.env` on the Mac.

These values are public by design. They are already compiled into the app's JavaScript.

`plugins/withCarPlay.js` writes them into Info.plist at prebuild, so native code can read them without React Native:

| Info.plist key | Value |
|---|---|
| `MBXAccessToken` | The public token. This is Mapbox's own Info.plist key. The CarPlay map also sets it explicitly, to the same value the iPhone's map sets from JavaScript. |
| `DerwentCarPlayMapStyleURL` | The Derwent style URL. |

The safety rules are the same as the Drive map's (`lib/mapbox.ts`):

- **Public tokens only.** The token must start with `pk.` and the style must be a `mapbox://styles/…` or `https://` URL.
- **Secret tokens stop the build.** An `sk.` token is never written; both `app.config.js` and the plugin stop prebuild if they see one.
- **Missing values give the placeholder.** If either value is missing or invalid, neither key is written and CarPlay shows the placeholder. It doesn't crash.

To confirm on the Mac, `node scripts/check-ios-scene-lifecycle.js` prints either "CarPlay shows the map" or "CarPlay shows its placeholder".

**Licensing and attribution:**

- Mapbox's logo and attribution stay visible on the CarPlay map. The attribution sits beside the logo, at the bottom leading corner, so CarPlay's map buttons at the trailing corner don't cover it.
- CarPlay doesn't pass touches to the map, so the attribution can't be tapped there. It's the same Mapbox data as the iPhone app.
- Mapbox bills per monthly active user. The CarPlay map runs in the same app install as the iPhone map, so it's expected to be the same user. Confirm with Mapbox if billing matters.

## The CarPlay interface (what Apple allows)

The design reference is a dark, premium, map-first look with Derwent's cyan accents. Apple's CarPlay rules come first:

- **The window draws map content only.** That means the Mapbox map and the position marker. No text, panels, buttons or alerts are drawn over the map.
- **All controls are CarPlay templates.** CarPlay draws them in its own style, so app colours don't apply to them.
- **Where Derwent's identity shows:** in the Derwent Mapbox style (the same dark style as the iPhone app), in the "Derwent" bar button, and in the app's name and icon on the CarPlay home screen.

The `CPMapTemplate` controls, kept to what works before navigation is connected:

| Control | Behaviour |
|---|---|
| Navigation bar: **Derwent** | The name (the map template has no title). Kept visible. Tapping it only logs. |
| Map button: **zoom in / zoom out** | One zoom level per tap, within zoom 3–20. |
| Map button: **recentre** | Goes to the car's position if it's shown, otherwise to the Great Britain overview. |
| Map button: **pan** | Opens CarPlay's panning mode: arrow buttons, or the car's knob. A **Done** button appears in the navigation bar; Apple requires the app to provide it. |
| Dragging (touch screens) | The map follows the finger. |

How the map behaves:

- **Starting view:** the phone's last known position at zoom 14, if location access was already granted and the fix is under 24 hours old. Otherwise it starts on Great Britain.
- **Position marker:** shown only if location access was already granted. CarPlay never asks for permission. The marker is display-only: it doesn't feed navigation, drive recording or location sharing.
- **Not built yet** (later milestones): search, routes and previews, guidance, trip estimates (ETA and distance), hazards, voice controls, map appearance options, and drive recording from CarPlay. Nothing on CarPlay shows made-up navigation data.

## Entitlement and Xcode signing

- **What prebuild writes:** `com.apple.developer.carplay-maps = true` goes into the generated entitlements alongside Sign in with Apple. The repository doesn't change signing.
- **What automatic signing needs:** a profile that includes the **CarPlay Navigation** capability, which is enabled on the App ID. Milestone 2 already built and ran in a car with it.
- **If Xcode reports the profile lacks `com.apple.developer.carplay-maps`:**
  1. Open Xcode → Settings → Accounts → your team, and choose **Download Manual Profiles**.
  2. Turn automatic signing off and on again.

Never edit `Info.plist`, the entitlements or `AppDelegate.swift` in Xcode: prebuild replaces them.

## Testing

### Build (Mac)

```sh
cd ~/path/to/Drive-OS
git fetch origin && git checkout claude/carplay-milestone-3 && git pull
pnpm install --frozen-lockfile
cd artifacts/mobile
cat .env                                  # must have EXPO_PUBLIC_MAPBOX_TOKEN (pk.…) and EXPO_PUBLIC_MAPBOX_STYLE_URL
npx expo prebuild -p ios --clean          # pod install lists DerwentCarPlay (0.2.0) and MapboxMaps
git restore package.json
node scripts/check-ios-scene-lifecycle.js # every line ✓, including "CarPlay shows the map"
open ios/Derwent.xcworkspace
```

If Xcode reports a Swift error in `modules/derwent-carplay`, send the error text. CI can't compile Swift.

### CarPlay in the iOS Simulator

1. Run on an iPhone simulator. Allow location when the iPhone app asks, and set a location with Features → Location → e.g. Apple or Freeway Drive.
2. In the Simulator, choose **I/O → External Displays → CarPlay**, then open Derwent.
3. Expected: the Derwent Mapbox map, with the Mapbox logo and "i" at the bottom left and four map buttons at the bottom right.
   - Xcode console (filter `CarPlay`): "CarPlay map created", "CarPlay map style loaded", "root template shown: true".
4. Try the controls:
   - Zoom in and out.
   - Recentre: goes to the simulated position, with the blue marker.
   - Pan: arrow buttons appear; tap **Done** to leave.
   - Drag the map.
5. Disconnect (External Displays → Disabled), reconnect, and open Derwent again.
6. Swipe the app away on the iPhone, then open it from CarPlay (CarPlay-first launch).
7. Check the iPhone app throughout: the Drive map, navigation and sign-in.

### Car

1. Build a Debug version to the iPhone with Xcode (or install the TestFlight build), and connect it to the car.
2. Open Derwent on the car's screen. Use it only while parked.
3. Check:
   - The map draws and is sharp at the car's screen size.
   - The logo and attribution aren't covered.
   - The buttons and panning work, including the car's knob or touch screen.
   - The position marker appears.
   - Disconnect and reconnect work.
   - A CarPlay-first launch (iPhone app swiped away) works.
4. With the phone locked: the map still draws, and the position marker moves while driving. This is the open question below.

## Known limitations and risks

- **Not compiled yet:** the Swift hasn't been compiled. The Mapbox calls follow the SDK v11 API that `@rnmapbox/maps` itself uses, but Xcode is the first real compile.
- **Locked phone [not verified]:** whether the position marker updates with the phone locked and only CarPlay showing. It uses "When In Use" or "Always" access, whichever was already granted.
- **Always dark:** the map uses the Derwent style regardless of CarPlay's light/dark setting. Day/night appearance is a later milestone ("map appearance").
- **Attribution position:** the 100 pt offset beside the logo needs checking on real screens.
- **No extra CarPlay screens:** no CarPlay Dashboard or instrument-cluster scenes yet.
- **Carried over from earlier milestones:** background relaunch (Milestone 1), and cold launch plus disconnect/reconnect in a car (Milestone 2).

## Rollback

- **Milestone 3 only:** run `git revert <Milestone 3 commit>`, then `npx expo prebuild -p ios --clean`. CarPlay is back to the Milestone 2 placeholder; the scene, entitlement and iPhone app are unchanged.
- **CarPlay entirely:** revert the Milestone 2 commit as well (`docs/SCENE_LIFECYCLE.md` describes the order). Then raise `ios.buildNumber` and archive as usual.
