# CarPlay (Milestone 2: minimal native interface)

Derwent is a CarPlay **navigation** app (Apple granted StarScale Ltd the CarPlay Navigation entitlement; it is enabled for the App ID `uk.co.starscale.drive.staging`).

This milestone only proves the integration:

- Derwent appears on the CarPlay home screen.
- Selecting it opens a minimal native interface: a map placeholder with a `CPMapTemplate`.
- Connecting and disconnecting are handled.

There is no map, location, search, routing or guidance on CarPlay yet. The iPhone app is unchanged.

| | Status |
|---|---|
| Native configuration generated by prebuild (scene, entitlement, autolinking) | Checked automatically (CI and `scripts/check-ios-scene-lifecycle.js`) |
| Swift compiles in Xcode | **Not yet checked**: CI runs on Linux, which has no iOS SDK |
| Derwent on the CarPlay home screen, launch, disconnect and reconnect | **Not yet checked**: needs the Simulator or a car (below) |

## Native architecture

```
Info.plist UIApplicationSceneManifest (generated by prebuild)
├─ UIWindowSceneSessionRoleApplication          → EXExpoAppSceneDelegate        (Expo; the iPhone app, unchanged)
└─ CPTemplateApplicationSceneSessionRoleApplication → DerwentCarPlaySceneDelegate  (this module)
      connect(interfaceController, CPWindow):
        window.rootViewController = CarPlayPlaceholderViewController   (map content only)
        interfaceController.setRootTemplate(CPMapTemplate)              ("Derwent" bar button)
      disconnect: releases the window content, the template and the interface controller
```

The local Expo module is `modules/derwent-carplay/`:

| File | Purpose |
|---|---|
| `expo-module.config.json` | Declares an iOS (`apple`) module. Expo autolinking finds it in `modules/`; there's no `package.json` and no JavaScript. |
| `ios/DerwentCarPlay.podspec` | The `DerwentCarPlay` pod, built from source as a static library, linking `CarPlay.framework`. |
| `ios/CarPlaySceneDelegate.swift` | `@objc(DerwentCarPlaySceneDelegate)`: the CarPlay scene delegate. |
| `ios/CarPlayPlaceholderViewController.swift` | The CarPlay window's content: Derwent's dark background with a faint grid. |

How it fits together:

- **Created by name.** UIKit creates the delegate from the class name in Info.plist. Nothing else in the app refers to it, so it is linked because CocoaPods adds `-ObjC` for static pods. Expo's own `EXExpoAppSceneDelegate` is found the same way.
- **Native-only.** The module doesn't import React Native, Expo or Mapbox. `scripts/check-ios-scene-lifecycle.js` checks this.
- **Doesn't depend on the iPhone app running.** It doesn't start React Native or read the location. A CarPlay-first launch, with the iPhone app not running, shows the placeholder without waiting for JavaScript.

### What Apple allows on the map template

- **Window:** a navigation app's CarPlay window may draw **map content only**. Alerts, overlays and other controls must come from CarPlay templates. So the placeholder is just a background, with no text or buttons.
- **"Derwent" label:** `CPMapTemplate` has no title of its own, so "Derwent" is a navigation bar button, the nearest supported control.
  - The bar is kept visible (`automaticallyHidesNavigationBar = false`).
  - Tapping the button only logs.
- **Home screen:** the CarPlay home screen shows the app's own icon and display name ("Derwent").

## Config plugin: `plugins/withCarPlay.js`

`app.config.js` lists `'./plugins/withCarPlay'`. The plugin:

1. **Info.plist:** adds the CarPlay scene (`CPTemplateApplicationScene`, delegate `DerwentCarPlaySceneDelegate`) beside Expo's iPhone scene.
   - It sets `UIApplicationSupportsMultipleScenes` to `true`, as Apple's CarPlay manifest does, so the iPhone and CarPlay can be on screen at once.
   - The iPhone scene, background modes and URL schemes are left exactly as they were.
2. **Entitlements:** adds `com.apple.developer.carplay-maps = true` alongside the existing ones (Sign in with Apple).

**Plugin order matters.**

- The scene manifest is created by `expo-build-properties` (`ios.enableSceneSupport`, Milestone 1).
- Config plugins' Info.plist steps run in *reverse* list order.
- So `./plugins/withCarPlay` is listed **before** `expo-build-properties`.
- If the order changes, or scene support is turned off, prebuild stops with an explanation. The plugin never guesses at or replaces the iPhone's scene.
- A unit test runs the real Info.plist steps in both orders to prove this.

Everything is generated by `npx expo prebuild -p ios --clean`. Two prebuilds produce identical files (CI checks this). Never edit `Info.plist`, the entitlements or `AppDelegate.swift` in Xcode, and don't add CarPlay through Xcode's "+ Capability": prebuild replaces those files.

## Entitlement and Xcode signing

- **What prebuild writes:** the CarPlay key goes into the generated `ios/Derwent/Derwent.entitlements`. Nothing in the repository changes signing: the team, automatic signing and the bundle ID stay as they are in Xcode.
- **What automatic signing needs:** a provisioning profile that includes the managed **CarPlay Navigation** capability. That capability is enabled on the App ID in Certificates, Identifiers & Profiles.
- **If Xcode reports that the profile doesn't include `com.apple.developer.carplay-maps`:**
  1. Open Xcode → Settings → Accounts → your team, and choose **Download Manual Profiles**.
  2. In Signing & Capabilities, turn **Automatically manage signing** off and on again, so Xcode fetches a fresh profile.
  3. Check that the App ID still shows CarPlay Navigation under Additional Capabilities.
- **Distribution:** the App Store distribution profile needs the same capability for TestFlight builds. Xcode creates it during Archive → Distribute.
- **Simulator builds:** these don't check provisioning, so the Simulator works before signing is sorted.

## Testing

### Build (Mac)

From `docs/TESTFLIGHT.md`, "Local Xcode build":

```sh
cd artifacts/mobile
npx expo prebuild -p ios --clean
git restore package.json
node scripts/check-ios-scene-lifecycle.js     # every line ✓
open ios/Derwent.xcworkspace
```

`pod install` (part of prebuild) should list `Installing DerwentCarPlay (0.1.0)`.

### CarPlay in the iOS Simulator

1. In Xcode, pick an iPhone simulator and press Run.
2. In the Simulator: **I/O → External Displays → CarPlay**. A CarPlay window opens.
3. Derwent's icon should be on the CarPlay home screen (swipe through the pages if needed). Tap it.
   - Expected: a dark grid with a "Derwent" button in the navigation bar.
   - The Xcode console (filter `CarPlay`) shows "CarPlay connected" and "CarPlay root template shown: true".
4. Close the CarPlay window (I/O → External Displays → Disabled). Expected: "CarPlay disconnected". Reopen it and launch Derwent again.
5. CarPlay first: quit Derwent on the simulated iPhone (swipe it away), then open it from the CarPlay window.
6. Throughout: the iPhone app still works, including the Drive map, navigation and sign-in.

Apple's separate **CarPlay Simulator** app (Additional Tools for Xcode) connects a real iPhone over USB. It's optional here, and hasn't been tried on this Intel Mac.

### iPhone and car

1. Build a Debug version to the iPhone from Xcode (cable), and keep Xcode's console open.
2. Connect the iPhone to the car's CarPlay (USB or wireless).
   - If Derwent's icon is missing, check iPhone Settings → General → CarPlay → the car → Customise.
3. Test these on the car:
   - **Launch from the car** with the iPhone app open, then again with it swiped away (CarPlay first).
   - **Disconnect and reconnect:** unplug or turn off the car, reconnect, and launch again.
   - **iPhone app still works** while CarPlay shows Derwent: Drive map, start and end a drive, navigation, sign-in.
4. Logs: Xcode console, or Console.app on the Mac with the iPhone selected, category `CarPlay`.
5. Only after that, archive for TestFlight. The TestFlight build is the one to try in the car without Xcode.

Use the car only while parked for these checks.

## Known limitations

- **Placeholder only:** no map, live position, search, routes, guidance or voice on CarPlay. The "Derwent" button does nothing.
- **No extra CarPlay screens:** no CarPlay Dashboard or instrument-cluster scenes. These are optional for navigation apps and come later.
- **Signed in or not:** the CarPlay screen looks the same whether or not the iPhone app is signed in. It shows no account data.
- **CarPlay-only launch:** the iPhone's React Native app starts only when its own scene connects (Milestone 1's scene lifecycle). The placeholder doesn't need it. The shared navigation engine on CarPlay (a later milestone) will.
- **Swift not compiled automatically:** CI can't compile Swift. The first compile happens in Xcode on the Mac.
- **Background relaunch:** still unverified on a phone (see `docs/SCENE_LIFECYCLE.md`).

## Rollback

1. Revert the CarPlay commit with `git revert <commit>`. That removes `plugins/withCarPlay.js`, `modules/derwent-carplay/`, the plugin entry, the tests and the CarPlay checks together, and keeps Milestone 1's scene lifecycle.
2. Run `npx expo prebuild -p ios --clean`. The `DerwentCarPlay` pod, CarPlay scene and entitlement are gone.
3. Raise `ios.buildNumber` and archive as usual.

To roll back Milestone 1 as well, do this first (`docs/SCENE_LIFECYCLE.md`).
