Expand the Existing Driving App: Garage, Journeys and Community

Extend the existing application without rebuilding it from scratch.

Preserve the current:

Mobile-first iPhone layout
Dark visual design
Orange accent colour
Bottom navigation
Existing map and navigation functionality
Existing Garage, Journeys, Community and Profile screens
Existing DVLA registration-lookup preparation
Existing local or database records

Before making changes:

Inspect the current project structure.
Identify the existing data models, routes, state management and reusable components.
Reuse existing components where practical.
Do not create duplicate Garage, Journey, Friend, Convoy or Community systems.
Do not replace working functionality unnecessarily.
Make database/schema migrations safely without deleting existing prototype data.
Test each feature after implementation.

The application is a driving companion ecosystem combining navigation, journeys, vehicles, friends, convoys, clubs, events and future OBD features.

1. Garage Improvements
Remove fuel-level entry when adding or editing vehicles

Remove the manual fuel-level slider and fuel-level percentage from:

Add Vehicle
Edit Vehicle
Vehicle creation forms

Fuel level is temporary live information rather than permanent vehicle identity data.

Keep the database field optional for future OBD or manual live updates, but do not ask for it during vehicle creation.

Do not display a fixed fuel percentage on Garage cards unless real or recently updated fuel information exists.

When no live fuel data exists, hide the fuel metric rather than displaying a fabricated value.

Fix vehicle deletion

The current Remove button does not successfully delete vehicles.

Implement a reliable vehicle deletion flow:

User presses Remove.
Open a confirmation dialog:
“Remove this vehicle?”
Explain that saved journeys will keep a historical snapshot of the vehicle.
Buttons:
Cancel
Remove Vehicle
Delete the vehicle only after confirmation.
Update the Garage list immediately.
If the deleted vehicle was active:
Automatically select another vehicle, if one exists.
Otherwise show a clear “No active vehicle” state.
Do not delete historical journeys associated with that vehicle.
Do not leave broken vehicle references.

Historical journey records should store a vehicle snapshot containing:

Vehicle ID
Make
Model
Nickname
Year
Registration, subject to privacy settings
Vehicle image
Key performance details at the time of the journey
Vehicle image upload

Ensure Add Vehicle supports:

Selecting an image from the device
Previewing the image
Replacing the image
Removing the image
Storing the uploaded image persistently
Showing an appropriate placeholder when no image exists

Do not require an image URL.

DVLA lookup

Keep the prepared registration lookup architecture.

Do not use fabricated lookup data.

Until live API access is available:

Clearly label it as Demo Mode.
Only return explicitly configured test data.
Unknown registrations must show that live DVLA lookup is not connected.
Keep manual vehicle entry available.
